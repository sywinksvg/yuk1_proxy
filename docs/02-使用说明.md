# 02 · 使用说明

## 一、典型场景：目标把我 IP 封了

**你说**：「这个站把我 IP 封了，换个出口再试」

**模型会调** `yuk1_escape(url)`，它自动做三件事：

1. **池内轮转**：从现有池挑出口试；遇到 403 / 429 / 验证码页 / 拦截页自动换下一个
   （单轮内同一代理最多 3 枪；同一目标优先复用上次成功的出口）
2. **都不行** → 对该目标跑一遍「WAF 模式验活」，筛出**真能打开这个站**的出口再用
3. **仍不行** → 自动补采一批新代理，再验活、再试

返回里有 `trace` 字段，能看出卡在哪一步：

```json
{"ok": true, "proxy": "1.2.3.4:8080", "status": 200,
 "trace": [{"stage": "pool_rotate", "ok": false, "blocked": ["5.6.7.8:3128 -> HTTP 403"]},
           {"stage": "waf_check", "alive_for_target": 2},
           {"stage": "pool_rotate_2", "ok": true, "status": 200}]}
```

**经验判据**（trace 到手怎么读）：

- `pool_rotate` 就成功 → 只是这个出口被封，换掉即可
- `waf_check` 筛出来是 0 → 现有池全打不动这个站，需要补充代理（见「缺国内 IP」）
- 全部阶段失败 → 可能是**频率防护**（不是 IP 封禁），这时**降频**比换 IP 更有效

## 二、需要国内 IP

打国内站点时，境外/机房 IP 常被直接 RST。用法：

```
yuk1_check(url="https://目标首页", cn_only=true)
```

它会**真的经代理请求一次**，读「出口 IP 的归属」，只保留中国的：

```json
{"alive": ["socks5h://a.b.c.d:1080"], "count": 1, "written": "ok_10001.txt"}
```

> 关键点：socks5 类代理的「出口」在**对端网络**，不是代理主机本身。所以归属要按
> 「经代理看到的出口 IP」判——工具内部就是这么做的。

验证完会自动写入池文件，之后 `yuk1_fetch` / 统一入口就会优先用这些。

## 三、日常出枪

```
yuk1_fetch(url="https://目标/api/xxx", method="GET")
```

返回：用的哪个代理、状态码、耗时、响应头、正文头部（≤800 字符）。

- 遇到 WAF 拦截会自动换出口重试（`blocked_by` 字段列出被拦的）
- 同一目标会记住上次成功的出口（连接更稳）

**成功但拿到拦截页**不会算成功——工具会识别常见的拦截特征再换。

**目标侧故障不换出口**：拿到 500/502/503/504 说明是目标自己出问题、与出口无关，
工具会**立即停止轮转**并返回真实响应（带 `target_error: true`），不白白烧代理。
同理，405 是服务端在正常回答「方法不对」，换出口没用——该换的是请求方法。

## 四、用 curl 走池（统一入口）

如果某个工具不方便走 MCP（比如你要用 curl / sqlmap / 浏览器），起统一入口：

```
yuk1_serve(action="start")     # 或命令行：uv run python yuk1_proxy.py serve
```

之后：

```bash
curl -x http://127.0.0.1:10001 https://目标
```

入口后端会自动从池里挑活代理，失败自动换下一个——**对调用方就是一个固定地址**。

hash 也支持明文 HTTP 目标（会自动改写请求行）。

> ⚠️ **直连兜底**：请求进来时如果池全挂/为空，入口会**用你本机 IP 直连**（保证入口永不失效）。
> 所以看到 200 不代表一定走了代理。三种确认方式：
> 1. **看响应头**（最直接）：`curl -sv -x http://127.0.0.1:10001 https://目标 2>&1 | grep -i x-yuk1-egress`
>    —— `proxy` = 走了池里的代理，`direct` = 用了本机 IP；
> 2. 访问显 IP 页面比对：`curl -x http://127.0.0.1:10001 https://api.ipify.org`；
> 3. 看入口日志的 `[direct] ...` 行。
>
> 不想让本机 IP 有机会露出去，就**关掉兜底**：设 `YUK1_PROXY_ALLOW_DIRECT=0`，
> 此时池空会直接返回 502（带 `X-Yuk1-Egress: none`），宁可失败也不直连。

管理入口：

```
yuk1_serve(action="status")    # 看是否在跑、PID
yuk1_serve(action="restart")   # 改了引擎代码后重启入口生效
```

## 五、看池子状态

```
yuk1_status()
```

```json
{"raw": 601, "ok": 32, "cn_ok": 1, "ok_10001": 1, "paid": 0,
 "nps_raw": [], "serve_10001": {"listening": true, "pid": 1234},
 "blacklist": 0}
```

| 字段 | 含义 |
|---|---|
| `raw` | 原始池（拉来的，未验活） |
| `ok` | 对目标验活通过的 |
| `cn_ok` | 确认中国出口的 |
| `ok_10001` | 统一入口正在用的池 |
| `paid` | 你自备的付费代理数 |
| `blacklist` | 当前被拉黑（失败）的条目数 |

## 六、命令行模式（不经 AI）

```bash
cd server

uv run python yuk1_proxy.py fetch                    # 拉免费源
uv run python yuk1_proxy.py fetch --cn               # 只拉并过滤中国源
uv run python yuk1_proxy.py check <URL> --limit 40   # 对目标验活
uv run python yuk1_proxy.py check <URL> --cn-only    # 只要中国出口
uv run python yuk1_proxy.py check <URL> --waf        # 拦截页也算失败
uv run python yuk1_proxy.py get <URL>                # 直接轮转出枪（调试）
uv run python yuk1_proxy.py doctor                   # 诊断
uv run python yuk1_proxy.py serve                    # 起统一入口（推荐常驻）
uv run python yuk1_proxy.py serve --watch 120 --auto-harvest 200
```

`serve` 的两个进阶参数：

- `--watch 120`：每 120 秒自动复验池里的条目，死的剔除、活的解禁
- `--auto-harvest 200`：池子快空时自动补采 200 个候选

## 七、自愈机制（不用管，但知道它存在）

| 机制 | 行为 |
|---|---|
| **失败拉黑** | 出枪失败的条目拉黑 10 分钟，不再被反复抽中；成功即解禁 |
| **存活巡检** | `serve` 每 120 秒复验池条目，死条从池文件剔除 |
| **自动回池** | 存活不足 3 条时，从候选池复验补回 |
| **分层取池** | 入口池（最新验活）优先，通用池兜底 |

实测效果：撞到死代理时第 1 枪约 14 秒（含超时），之后降到 0.4 秒。
